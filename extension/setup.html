Legacy Chrome connection setup

SlotDesk 0.9.5 also supports an independent Google account window after one-time owner hosting setup. Follow the release’s Browser sign-in activation guide for that path. The form below configures only the older Chrome Extension OAuth client; never enter a Web application client secret here.

Updating an existing pilot? Keep the existing OAuth client and extension key. Review the event-writing scope in Data Access, reload and reconnect. Scope update notes.

Complete this setup before sending the ZIP to a tester. Testers follow START-HERE.html to install and connect; they do not configure Google Cloud.

1. Install the extension

  1. Extract the SlotDesk ZIP into a folder that will stay on your computer.
  2. In Chrome, open chrome://extensions, turn on Developer mode, and choose Load unpacked.
  3. Select the folder containing manifest.json. Pin SlotDesk, then click its icon to open the side panel. Use Open full workspace for a larger view.

Use the Chrome profile for the Google account you want to test. Calendar sharing in that account determines which other people’s calendars are available.

Stable pilot extension ID:

Load this page inside the extension to see its ID.

2. App owner: configure Google once

  1. Open Google Cloud Console and select or create the project that will own SlotDesk.
  2. Enable Google Calendar API in APIs & Services → Library.
  3. In Google Auth Platform, configure the app branding and audience. For an external pilot, keep the app in Testing and add Nina’s Google account and your testing account as test users. An organization-only app can use Internal where available.
  4. Under Data Access, add the three requested scopes listed below. Under Clients, create an OAuth client of type Chrome Extension. Use the pilot extension ID above as the Item ID.
  5. Paste the client ID below. Download the configured manifest, replace manifest.json in the extension folder, then click Reload in Chrome’s Extensions page. Give Nina a ZIP of that configured folder.

    3. Tester: connect and test

    Follow START-HERE.html: connect Google, save your own email/name/timezone profile, choose a default invitation calendar, add people and find a time. All details and warnings are reviewed before Create & send invitations. Acceptance walkthrough.

    Updating from read-only access

    Since 0.3.0, SlotDesk requests calendar.events, calendar.calendarlist.readonly and calendar.events.freebusy. The event scope replaces read-only access so reviewed meetings can be created on writable calendars. Keep the existing OAuth client, pinned extension key and pilot audience. Review the three scopes in the existing project's Data Access configuration, then reload and reconnect to grant the requested access. Live consent, invitations and Meet generation still require testing.

    If connection fails

    • App not configured: complete step 2, replace the manifest and reload the extension.
    • Access blocked / not a test user: add the intended Google account in the app’s test audience. A managed Workspace account may need administrator approval.
    • Wrong account: use the intended Chrome profile, then disconnect and reconnect.
    • Missing calendar: share or subscribe to it in Google Calendar using the connected account, then search again.
    • Unconfirmed proposal: check Calendar data for failed sources, missing mappings or unavailable calendars before relying on the time.

    Pilot sign-in and real-account behavior still require an end-to-end check after the owner configures Google. The local build alone cannot validate your account’s OAuth and calendar-sharing setup.
