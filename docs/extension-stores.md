# Extension-store readiness

Publication status as of 8 November 2026: SlotDesk **1.0.0** is public on Chrome, Edge and Firefox. See [installation](install.md) and [store identities](store-kit/store-identities.md) for the confirmed listings. Store publication, Google authorization and native install/update testing are tracked separately.

## Release checks and decisions

1. The server-side Google connection was activated on 21 October. Keep [the consolidated guide](browser-signin-setup.md) as the configuration reference and record real-provider verification for each store build. Store review, OAuth verification and workplace administration are separate.
2. Use support@buildwithspeedy.com and https://buildwithspeedy.com in store support/website fields. The verified public privacy-policy URL is https://buildwithspeedy.com/slotdesk/privacy. Explain that Google codes/tokens pass transiently through the auth service, calendar operations stay direct to Google, local credentials are session-only, and the leads table receives confirmed email/name/timezone, browser label, completion time, updates choice and onboarding UUID. State required Chrome/Edge registration, optional Firefox registration sharing and the separate optional updates checkbox accurately. Review each store's data/consent policy before submission; do not silently relabel or remove the agreed leads feature.
3. MIT is adopted and the source repository is public; include its link in final store descriptions and dedicated source-code fields where supported. Use the approved SlotDesk/Speedy product and publisher names, credit Speedy, Nina Banai and Yoav Fried, and preserve third-party font/data notices. Add listing links back to the repository only once real installation destinations exist.
4. The selected toolbar icons are bundled, and current synthetic-data screenshots and both Chrome promo tiles are prepared in the store kit. Reuse them only where they match the submitted build; check each platform's current dimensions. Existing wordmark/design-kit assets remain authoritative. Never substitute private calendar screenshots.
5. Record each store-issued extension ID, corresponding exact OAuth return/origin and update origin. A new origin does not automatically inherit local profiles; provide the existing portable-configuration route if identity changes. Never put client secrets or Google credentials in a store package.
6. Validate install → update → account switch → browser restart, native sidebar/full-tab behavior, permission cancellation/revocation, file/clipboard fallbacks and shared-window write guards on the intended browser/OS. Include synthetic integrity cases and one controlled real-provider sign-in check. Provide reviewers a functioning approved route; do not bypass Google's test audience.
7. Before wider rollout review service capacity, hosting-level abuse limits, key rotation, credential-free operational logging and support. Current per-instance throttles are coarse, not global rate enforcement. Future public scale and any Google quota/billing policy need a current separate assessment.
